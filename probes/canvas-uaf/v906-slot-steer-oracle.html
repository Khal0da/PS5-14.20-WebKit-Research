V906 - Canvas UAF slot-steer oracle (offset-agnostic)

Question: after an ArrayBuffer(768) reclaims the freed CanvasRenderingContext2D slot, does the stale wrapper actually dereference bytes inside that slot? And if yes, which offset is the state vector? V650 forged +112 and all 30 targets crashed, so either the offset is wrong or the slot is never read.

Idea: stop guessing the offset. Fill the whole 768-byte slot with a repeating [ptr, size=1, cap=1] 16-byte pattern. Any 8-byte-aligned Vector offset then sees m_buffer=ptr, m_size=1, m_capacity=1. Two phase orders (pe = pointer first, po = size word first) cover every possible offset, because a Vector is 8-byte aligned and the period is 16.

Built-in miss detector: after the AB spray the page allocates 8 real 2d contexts with lineWidth = 200..207 and then reads savedCtx.lineWidth.
• 200..207 = the AB missed the slot (a real context took it) → no conclusion, rerun.
• crash = the AB took the slot and the forged pointer was rejected (unmapped / bad size).
• any other number = HIT: the AB took the slot and the read came back from the forged pointer.

Start: ?op=auto  |  one case: ?case=pe_4m  |  clear: ?reset=1
After a crash just reopen ?op=auto. Done when the page prints ALL CASES DONE.
