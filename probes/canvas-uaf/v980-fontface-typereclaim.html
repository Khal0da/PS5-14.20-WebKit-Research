V980 - CSSFontFace UAF: survivor-mode type reclaim on 14.20

Why V980: V979 confirmed the trigger (24 real HIT / 28 valid armed runs) but showed two dead ends: the cascade never corrupts more than one face, and case=types crashed 100% right after TYPEWAVE made=256 with no TYPECHECK - i.e. we do land on a live JS object but always die before we can read it. V980 keeps the V979 trigger and changes only the measurement: (1) type spray is now small and tiered (tn, default 24) so the renderer survives to the check; (2) TYPEPRE logs the family/index before allocating so crash-to-family mapping is explicit; (3) TYPECHECK runs after a delay, then TYPECHECK2 1.2 s later, and reports how many held objects survived and how many signatures changed; (4) reset=1 no longer clears typeidx, so the family sweep continues instead of restarting at 0; (5) the timer oracle is fixed - timer spray faces are plain local() faces that are never preloaded, so any status change can only come from the writeback (V979's hit=68 was a false positive: every face naturally became error on the dead 192.0.2.1 URL). Cases: all|cascade|types|promise|timer|status (default all = cascade+promise+status). &k=N face spray (64), &tn=N type spray (24), &maxloads=N (10), &typeidx=N family override, &arm=0 control, &stop=1.
