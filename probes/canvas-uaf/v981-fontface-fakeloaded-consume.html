V981 - Can a fake-loaded CSSFontFace be consumed dangerously?

Why V981: V980 proved the trigger is a reliable single-face status flip with survival (hit=1, one of 64 sprayed faces becomes loaded, controls stay unloaded), and that any non-CSSFontFace reclaim dies in the setStatus tail (m_timeoutTimer.stop()). So the only survivable reclaim is a real CSSFontFace, and the only observable effect is m_status=Loaded on a face that was never loaded (fake-loaded: m_font is still null). This probe asks the last question: does any consumer trust status()/check() and then dereference the missing font? It runs the same trigger, then feeds the hit family to DOM text, SVG <text> (getBBox/getComputedTextLength), Canvas 2D fillText + pixel readback, weight/style mismatch matching, and an SVG data-URL image. Every step is preceded by a PHASE beacon so a crash maps to the exact consumer. Cases: ctx (default) | control | all (cascade). &k=N spray (64), &arm=0 baseline, &print=1 optional window.print(), &stop=1.
