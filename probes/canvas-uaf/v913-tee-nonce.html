V913 - tee() nonce readback

Goal: settle the tee() read question with fresh nonces per load, not a fixed pattern. V904 closed under-yield as short-vector DoS and the V8xx "leak" was the probe's own fixed bytes. V827's 071421... is the probe's incremental pattern (+7 per byte), deterministic because the data is deterministic — not because the heap is. Idea: enqueue 32 random nonce bytes + 0xA5 padding, tee(), read both branches. If readback == nonce exactly (same length, sameObject noted, padding intact) and the hex differs next run (fresh nonce), that's a self-data round-trip — no leak. Any extra bytes beyond enqueued size, a length mismatch, or pointer-like hex where nonce should be = foreign data = controlled read (would be a first). An incremental +7 control runs alongside to show why fixed patterns look "deterministic".

Start: just open the page. Runs once, prints TEE DONE. Beacons prefix: V913-. Run it twice — nonces must differ between runs, readbacks must match their own run's nonce.
