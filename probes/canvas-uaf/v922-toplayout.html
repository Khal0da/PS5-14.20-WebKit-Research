V922 - user-space width scan for ps_strings

V921 disproved the LA48 anchor: 0x7fffffffe000, 0x7fffffffefe0, 0x7fffffffdfe0, 0x7fffffffd000 all crashed. The PS5 WebContent process is not using the standard 48-bit top-of-user-space layout. This probe walks the usual user-space widths (max = 2^(n-1)) and reads ps_strings at max - 0x1020 (stage 1), then the lowered-shared-page variant at max - 0x2020 (stage 2). Read primitive is unchanged: lineWidth = *(m_buffer + (m_size-1)*400 + 48). A surviving read at ps_strings = ASLR defeated.
