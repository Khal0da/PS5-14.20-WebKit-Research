V919 - m_size address sweep (module range)

The missing dimension (from the 11-07 review): V906 forged [ptr,1,1] - m_size was fixed at 1, so each load tested exactly ONE address. But the read is lineWidth = *(m_buffer + (m_size-1)*400 + 48) and both m_buffer AND m_size live in our AB - m_size is a 32-bit index with a x400 multiplier, JS-rewritable between reads! From any base, m_size covers base..base+1.7TB in 400B steps. A mapped probe returns 8 bytes (x5 offsets with the extra reads) and the sweep CONTINUES in the same load; an unmapped probe crashes (= the region boundary - the crash itself maps memory). Target: PS5 libWebKit base range [0x800000000, 0x900000000), 0x4000-aligned (derived from the official chain's site.js). Each case = one random 16KB-aligned candidate; if the first probe survives we are inside a mapping and the load leaks the region until the boundary. forge-ctl validates the mechanism (crash expected). Resume: surviving sweeps continue across loads (up to 1500 probes/case); crashes end the case. Beacons: one per surviving probe (k + 5 hex values).

Start: ?op=auto  |  one case: ?case=sweep-001  |  clear: ?reset=1
After a crash just reopen ?op=auto. Done when the page prints ALL CASES DONE.
