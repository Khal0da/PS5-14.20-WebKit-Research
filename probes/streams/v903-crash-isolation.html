V903 - tee() crash isolation

Purpose: find where the under-yield tee() dies, not to read a freed slot. One case per page load (one shot per WebProcess). The last stage reached is written to localStorage synchronously before the next step, so if the WebProcess dies the next load reports CRASH last=<case>:<stage>. No per-stage network traffic inside the iterator, so the heap is not groomed by the harness itself.

Start: ?op=auto  |  one case: ?case=y1  |  clear: ?reset=1

Safety: cases y1, y1_doneval, y1r2, y1_noise, y0, w_y1 are expected to kill the WebProcess. Re-open ?op=auto after a crash; the harness records CRASH and continues with the next case.

Cases

ctl          normal tee(), no iterator poison                      (control, must survive)
y2_stream    iterator yields 2 real ReadableStreams               (size 2)
y2_plain     iterator yields 2 plain objects                      (size 2, wrong shape)
y2_ab        iterator yields [ArrayBuffer, plain object]          (size 2, wrong type)
y2_undef     iterator yields [plain, undefined]                   (primitive -> TypeError expected)
y2_null      iterator yields [plain, null]                        (primitive -> TypeError expected)
y2_num       iterator yields [plain, 1]                           (primitive -> TypeError expected)
y3           iterator yields 3 plain objects                      (over-yield, size 3)
same2        iterator yields the SAME object twice                (size 2, private-slot inversion)
y1_throw     1 item, then next() throws                           (exception path)
own          fresh 32-byte random nonce -> tee -> read -> compare (provenance control)
w_y2         y2_stream inside a Worker                            (worker control)
y1_doneval   1 item, then {done:true, value:object}               (is done-value used? expect crash)
y1r2         1 item, then done                                    (repeatability)
y1_noise     1200 allocated objects, then 1 item, then done       (heap-noise invariance)
y0           iterator returns done immediately (0 items)          (expect crash)
w_y1         1 item, then done, inside a Worker                   (process vs worker death)
w_y1inf      1 item, then infinite done:false, inside a Worker    (hang vs crash discriminator)

own answers the "did we read our own data?" question directly: it writes a fresh random nonce into a 64-byte buffer, tees it, reads branch 1, and reports whether the 32 nonce bytes came back unchanged. If nonceMatch=true, the bytes are owned by the test; they are not evidence of unowned memory.

Worker cases use v903-worker.js (same origin). If the whole WebProcess dies on w_y1 the main thread never sends V903-MAIN-ALIVE; if only the worker spins, V903-MAIN-ALIVE arrives and the worker is terminated. That is the crash-vs-hang discriminator.

Crash report / stack: the harness gives the exact last stage and a deterministic signature. A native stack trace still needs the console's own log (/dev/klog). If a loader is reachable on the console (port 9027) run: python3 tools/send.py <PS5_IP> 9027 payloads/klog.js --arg follow --arg sec=120 --arg grep=WebProcess before re-running the crashing case. Without that, the last-stage + worker discrimination below is the strongest device-side evidence available.
