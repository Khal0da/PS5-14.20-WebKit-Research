# Full Review -- CVE-2026-43720 Exploitation (2026-11-07)

Re-review of the entire chain after V907-V914 closed the in-browser leak hunt.
Purpose: find what was missed. Result: 4 genuinely untested surfaces + 2 structural
re-derivations that change how we read old results.

## 1. The Bug (CONFIRMED, solid)

`HTMLCanvasElement::getContext()` reads dictionary options via JS getters BEFORE
swapping the context. Re-entrant getter creates a 2d context (768B); the outer
bitmaprenderer assignment frees it while the JS wrapper survives.

Trigger rules (all device-verified):
- outer MUST be bitmaprenderer (~80B, different class), inner MUST be 2d (768B)
- MUST use defineProperty (not Proxy)
- one UAF per page load

PS5 enablers: IsoHeap OFF (BPlatform.h:341) + Gigacage OFF -> one bmalloc heap.

## 3. The wall (structurally re-derived)

The exploitation design (forge dash vector in AB-reclaimed state buffer -> arb R/W)
is SOUND but needs ONE known-mapped address. Re-derivation of why each escape closes:

1. Forge in AB -> absolute address required (V650/V906: all guesses unmapped).
2. Same-type reclaim -> wrapper IS the owner; reads return owner values (V908
   save-count desync impossible: wrapper reads live m_size).
3. JSC side (butterflies/JSMap) -> different allocator (V910: 10/10 MISS).
4. JS-exposed numbers -> none pointer-derived (V912).
5. tee() -> self-data only (V904+V913).
6. Natural WebCore 705-768B allocations -> +112 always data (175 cases, V907-V914).

## 4. What was missed -- re-examination findings

### 4.1 State layout re-derived (matches V592 exactly)

CanvasRenderingContext2DBase::State (no vtable, plain struct):
  strokeStyle (CanvasStyle, 24B) @ +0
  fillStyle   (CanvasStyle, 24B) @ +24
  lineWidth   (double)         @ +48   <- V592 measured lwOff = 12848 = 32*400 + 48
  miterLimit/globalAlpha/lineDashOffset/shadowBlur follow as doubles (+56..)

CanvasStyle = { m_type (4B), pad(4), union { Color / RefPtr<CanvasPattern> /
RefPtr<CanvasGradient> } (8B) } -> **the RefPtr sits at style_offset + 8**:
strokeStyle ptr @ +8, fillStyle ptr @ +32.

### 4.2 V683 re-interpretation (freed-not-reclaimed crash)

Old conclusion: "reading a freed, not-yet-reclaimed context crashes at first touch".
Re-interpretation: between the free and the read, the page performs other allocations
(teardown, beacons) - the freed 768B block is almost immediately reused by an
UNCONTROLLED allocation whose +112 is garbage -> crash at the state() deref.
This is NOT a vtable wall: V906 proved the read path reaches the +112 deref
(forged-ptr crash), and a live-alias read works fully. **The call path
(wrapper -> cast -> impl->lineWidth() -> m_stateStack.last()) has no vtable gate
for these non-virtual getters.**

### 4.3 NEVER-TESTED reads: fillStyle / strokeStyle through the stale wrapper

The SUSPECT extra reads were only numeric doubles (ml/ga/ldo/sb at +56..).
**`innerCtx.fillStyle` / `innerCtx.strokeStyle` were NEVER read through the stale
wrapper.** These exercise CanvasStyle -> JS wrapper conversion, including the
RefPtr<CanvasPattern> path. Scenarios:
- live alias: returns the tagger's style (no leak) - safe control case.
- AB reclaim (zero +112): state() deref -> crash (expected).
- **stale-tail reclaim (4.4): state() derefs the stale SB pointer (freed-but-mapped)
  -> State[32].fillStyle ptr -> if the pattern was released (context free) and its
  refcount hit 0 -> toJS() on a freed CanvasPattern = SECOND-ORDER UAF on a pattern
  object whose slot we may control.** Never tested.

### 4.4 NEVER-TESTED: stale-tail (partial-write) reclaim of the slot

The 768B slot reclaimed by an allocation that WRITES LESS than 112 bytes leaves
+112 = the old m_stateStack pointer (freed-but-mapped SB). Candidates:
- WTF Vector with large INLINE capacity crossing +112, constructed with fewer
  elements than inline capacity (inline tail = stale).
- Any exact-size object whose constructor initializes only its head.
Consequences if it works:
- lineWidth returns SB[32].lineWidth = 3.14159 (our known value) -> **first readable
  return ever (SUSPECT milestone)** - proves the freed-memory read channel.
- m_size (+120) stays stale = 33 -> state().last() = SB[32] (written). The unwritten
  capacity tail SB[33..36] is NOT reachable (m_size gated) - so this is a channel
  milestone, not yet a leak.

### 4.5 NEVER-TESTED: double-UAF inside ONE trigger

The options dictionary parses attributes IN ORDER. alpha getter creates ctx A (2d).
**A second getter (colorSpace/willReadFrequently) creating ctx B (2d) frees A
immediately** - then the outer assignment frees B. Result: TWO freed 768B slots +
TWO stale wrappers from a single trigger. The "never trigger twice" rule was about
separate outer calls; the two-getter variant was never tested. Two slots double the
reclaim surface (e.g., one slot live-aliased for R/W, one AB-reclaimed for forging).

### 4.6 mmcl 4/4 CRASH - plausible mechanism (unverified)

If the landing allocation is the MediaQueryExp vector (32B/exp: String ptr @0,
type @8, Vector m_values @16-31), +112 = element[3].m_values.m_buffer. For any
clause with an empty/zero value vector that field is NULL -> deref NULL+48 -> crash.
All mmcl clauses had values, so either the exp vector did not land (query string did)
or a different field is at +112. **Source-exact layouts would resolve this.**
