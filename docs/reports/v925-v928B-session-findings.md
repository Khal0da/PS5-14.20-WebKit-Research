## 2) What this proves

- **Same-type alias is alive and stable on 14.20** (V573 pattern): UAF → spray 2D (no stale-ctx touch before spray) → confirmed alias + typed state R/W + stable `getLineDash/setLineDash` (incl. growth).
- **V923/V924 class is blocked in its current form:** V925 shows any call on the **stale wrapper** after free (`lineWidth` read / `save`) crashes, and `pf-spray-save` (AB spray + `save` canary) crashes — so “AB owns slot + call `save/roundRect/moveTo` on stale ctx + scan AB for WebKit-written pointer” **cannot complete** on 14.20 as implemented.
- **AB spray+scan alone** survived but reported `hits=0` (no visible aliasing of the freed slot by those zeroed ABs in that case).

## 3) The remaining wall

- **Info leak / ASLR (heap pointer, raw bytes)** remains unsolved in-browser for this chain. Alias gives **typed** state-field R/W, not raw object memory / pointers. Forging vector metadata without a known **mapped** address returns to the blind crash-oracle problem (per `docs/STRATEGY.md`, in-browser surface largely exhausted).
